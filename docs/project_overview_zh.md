# TALOS 桌面抓取项目说明

> **当前实验状态（2026-09-04）：初步锚点探索失败。** 当前 800 候选仅 66 个通过物理验证，所有 stage 都没有达到每级 10 个有效锚点的门槛。现有候选库不得用于正式泛化站立训练，失败原因与下一轮门禁见[初步锚点探索失败报告](initial_anchor_exploration_failure_report_zh.md)。

## 1. 项目目标

本项目研究 TALOS 人形机器人在 **base 不固定、双脚保持原地接触并自主平衡** 的条件下，使用真实耦合三指夹爪完成桌面物体操作。最终任务是：

1. 从桌面主动接近并夹持物体；
2. 将物体稳定抬离桌面；
3. 搬运到目标区域并释放；
4. 将仿真策略迁移到真实 TALOS。

当前只训练第一个技能，即右手抓取并稳定抬升物体。搬运与放置将作为独立策略，在抓取成功状态上继续训练。

## 2. 为什么采用反向课程

如果直接让 PPO 从站立姿态随机探索，成功抓握是极低概率事件，策略容易学到碰撞、推物体或短暂弹起物体等局部最优。项目因此从任务终点附近开始训练：先学习维持已经形成的稳定抓握，再逐渐把初始状态向“夹爪张开、手掌远离物体、姿态误差更大”的方向扩展，最终覆盖完整抓取过程。

整个流程为：

```text
IK 生成分散候选
  -> 物理仿真验证站立与接触
  -> 每个难度保留永久锚点
  -> PPO 从相邻难度混合采样
  -> 成功轨迹跨越边界后扩充状态库
  -> 逐步开放更困难的初始状态
```

该方法不按单个关节或扰动类型硬切课程，而是在任务坐标中衡量每个状态距离成功抓握有多远。

## 3. 仿真模型与任务约束

- 仿真框架：MJLab 1.5.0，集群使用已经验证的共享 MJLab 环境；
- 机器人：PAL Robotics TALOS；
- base：自由浮动，不使用固定关节；
- 手：保留单电机三指机械耦合、被动关节和手指接触 mesh；
- 传感器：保留腕部与踝部 F/T 接口以及手物接触传感器；
- 物体：当前为边长 60 mm 的自由刚体立方体，没有焊接或运动学附着；
- 桌面：顶面高度 0.86 m 的固定长方体；
- 物体尺寸、质量和摩擦：当前阶段保持固定，待完整抓取动作学会后再进行域随机化。

夹爪主关节约定需要特别注意：约 `-0.959931 rad` 表示闭合，`0 rad` 表示张开。课程生成和状态分类均使用这一物理方向。

## 4. 策略接口

当前稳定接触抬升任务沿用已训练站立策略的网络接口：

| 项目 | 当前定义 |
| --- | --- |
| Actor 观测 | 222 维 |
| Critic 观测 | 225 维 |
| 动作 | 29 维关节位置目标 |
| Actor 特权信息 | 机器人坐标系中的物体中心真值 |
| Critic 额外信息 | 包含 base 线速度 |
| 控制范围 | 双腿、躯干、双臂和右夹爪 |

现阶段使用物体中心真值训练 privileged teacher。后续保持物体位置接口维度不变，把 actor 侧真值替换为视觉估计，再蒸馏到只依赖实机可获得感知的 student。

## 5. Stage0：8 cm 稳定保持

任务 ID：`Mjlab-Tabletop-Stable-Contact-Lift-Cube-Talos-v0`。

Stage0 从全身 IK 得到的空中抓握姿态开始。方块中心位于其桌面初始中心上方 **8 cm**，且始终是自由刚体。该阶段的目的不是学习接近，而是确认策略能在保持站立的同时持续施加有效夹持力。

主要奖励和约束如下：

| 项目 | 作用 |
| --- | --- |
| 当前抬升高度 | 只奖励当前仍保持多链接接触时的真实抬升，不记录历史最高点 |
| 目标高度误差 | 以 8 cm 为中心的高斯奖励，标准差为 2.5 cm |
| 物体速度门 | 物体速度越大，目标高度奖励越低，抑制抛掷策略 |
| 多链接接触 | 至少两个不同手指链接接触物体 |
| 接触面与 force closure | 鼓励能抵抗任务 wrench 的接触分布 |
| 站立约束 | 奖励竖直、双脚接触和低 base 漂移，惩罚滑脚与异常姿态 |
| 弹飞与过高惩罚 | 防止用瞬时冲击获得高度奖励 |

一次成功必须同时满足：

- 有效抬升高度位于 `8 ± 1.5 cm`；
- 至少两个独立手指链接接触；
- 抓握质量超过最低阈值；
- 手物相对速度不超过 `0.08 m/s`；
- 物体线速度不超过 `0.12 m/s`；
- 上述条件连续保持至少 5 秒。

接触传感器输出显式转换到世界坐标后再计算抓握质量，避免把局部坐标系中的力和世界坐标中的几何量混合。

## 6. Stage 1–20 状态难度

状态分类器把任意有效站立状态转换为以下九个归一化任务误差：

1. 手物轴向距离；
2. 手物横向距离；
3. 手腕旋转误差；
4. 夹爪张开比例；
5. 关节极限风险；
6. base 倾斜；
7. base 线速度；
8. base 角速度；
9. 手物相对速度。

综合难度以最大误差为主，并以较小权重加入其余误差的平均值。这样既不会让危险的单项误差被平均掉，也能区分一个误差很大和多个误差同时偏大的状态。严格验证、低速且稳定的抓握单独归为 Stage0，其余状态映射到 Stage 1–20。

课程初始化分布为：

- Stage 1–19：上一难度 30%，当前难度 60%，下一难度 10%；
- Stage 20：Stage19 占 30%，Stage20 占 70%。

升级只统计从当前难度初始化的 episode。完成至少 4096 个当前难度 episode 后，抓取物体并在 8 cm 目标高度连续保持 5 秒的成功率必须严格大于 80%，才允许开放下一阶段。

## 7. 锚点与动态状态库

每个难度先由 IK 生成 10 个尽量分散的永久锚点。候选状态必须恢复到完整物理环境中，并使用已训练的稳定站立策略验证，不接受仅在运动学上可达但会倒地、穿透或立即失去接触的状态。

后续动态状态库遵循以下原则：

- 保存完整可恢复状态，而不是只保存关节角；
- 轨迹进入更简单难度并跨过边界一段时间后，才考虑保存；
- 保存边界后短轨迹的中间帧，避免边界抖动状态；
- 降级到 Stage N 只说明该状态属于 N，不预先假设它能完成 N 到 N-1；
- Stage10 以后在 reset 时加入小扰动以扩展覆盖；
- 每个难度最多保留 10,000 个状态，去重时永久保留 IK 锚点。

目前已经实现状态分类、课程分布、升级判据、IK 候选生成、物理筛选工具和锚点 reset 代码路径。但初步候选库没有通过物理与人工检查，训练中自动回写状态库和去重仍是下一阶段工作。

## 9. 运行与验证

本地代码检查：

```bash
uv sync --extra cpu
uv run ruff check .
uv run pytest
```

集群训练使用 `slurm/mjlab-grasp-train.sbatch`。应通过 `TASK`、`NUM_ENVS`、`MAX_ITERATIONS`、`RUN_NAME` 和初始化 checkpoint 环境变量提交，不需要为每次代码更新重新构建容器镜像。

锚点流程使用 `slurm/mjlab-build-anchors.sbatch`：先生成候选，再加载稳定站立 checkpoint 进行并行物理验证，最终把每个难度的 10 个锚点写入集群数据目录。

锚点泛化站立任务使用 `Mjlab-Tabletop-Anchor-Standing-Cube-Talos-v0`。它已具备从 `TALOS_STANDING_ANCHOR_BANK` 指向的 20-stage 锚点库随机初始化，并用三级 domain randomization 逐步扩大关节/基座/物体初态、摩擦、PD 增益、编码器偏置和外部推扰范围的代码路径。每级满 8192 个完成 episode 后，仅当连续稳定站立 5 秒的成功率严格高于 80% 才升级；目标规模为并行 2048 个环境。由于本轮锚点探索失败，在新锚点库达到准入条件前不得启动正式训练。

## 10. 当前完成度与风险

已经完成：

- TALOS、桌面、自由物体和真实耦合夹爪建模；
- privileged-position 抓取任务与站立策略权重迁移；
- Stage0 的 8 cm 稳定保持奖励和成功判据；
- Stage 1–20 状态分类、混合采样定义和升级门槛；
- IK 锚点候选生成、物理验证和可视化脚本；
- 锚点 reset、三级 domain randomization 和基于成功率的站立课程代码路径。

仍需验证或实现：

- 当前空中 IK 种子需要策略主动维持，不能被视为被动稳定夹持；
- 修复夹爪过闭合、base/下肢无多样性和方块未与手部目标联合生成的问题；
- 重新生成并验证 Stage 1–20 每级至少 10 个物理有效锚点；
- 验证 Stage0 是否真正学会持续夹持，而不是利用碰撞或姿态漏洞；
- 仅在锚点库达标后启用正式训练 reset；
- 实现跨难度轨迹收集、去重与容量管理；
- 完成从 Stage0 到完整桌面抓取的连续反向课程；
- 加入物体尺寸、质量、摩擦、感知噪声和延迟随机化；
- 训练视觉 student 并进行 sim-to-real 评估。

因此，当前版本是反向课程基础设施和 Stage0 奖励重构后的训练候选版本，还不是已经完成的端到端抓取系统。
